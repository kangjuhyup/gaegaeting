# 산책코스·산책 기록·일기 백엔드 구현

사용자의 기능 구현 요청과 2026-10-05 추가 지시를 반영한다. 이번 범위는 `packages/challenge` 백엔드이며 사용자 화면은 완료 후 Flutter 앱 에이전트가 연결한다. [제품 기획](2026-10-05-walking-routes-and-challenges.md)의 코스 공유·완주·일기·챌린지 흐름을 기준으로 한다.

## 구현 계약

- `route`: 본인의 종료된 산책에서 연속 구간을 선택해 코스를 만든다. 공개 좌표에는 위도·경도만 포함하고 원본 시각·정확도·잘라낸 구간은 노출하지 않는다. 초안 → 검토 중 → 공개/반려, 작성자 공개 중단과 관리자 게시 중단, 주변 탐색·저장·신고·조회 API를 제공한다. 공개 경로 변경은 새 코스로 작성한다.
- `walk`: Account에서 보호자 프로필과 선택한 반려견 소유권을 확인하고 서버에 시작을 등록한다. 사용자당 진행 중 기록 하나, 시작 UUID 재시도, 순서가 있는 좌표 배치 업로드·중복 재전송·일시정지·재개·종료·본인 조회·삭제를 지원한다. 시작한 코스의 공개 경로와 판정 정책을 고정한다. 원본 위치 기록은 본인에게만 반환한다.
- `diary`: 종료된 본인 산책에 본문·기분·사진을 저장한다. 기본 비공개, 명시적 공개는 완주한 공개 코스의 후기로만 허용한다. 한 사용자의 같은 코스 공개 후기는 최신 한 개로 유지한다. 공개 응답은 본문·사진·기분·한국 날짜와 표시 이름만 포함한다.
- 사진은 전용 비공개 S3 호환 저장소에 업로드한다. 서버가 크기·PNG 실제 디코딩을 검증하고 픽셀을 재인코딩해 위치 등 메타데이터를 제거한 별도 객체로 확정한다. 서버가 확인한 사진만 챌린지 조건에 반영한다. 삭제 작업은 DB에 재시도 가능한 정리 작업을 남긴다.
- 종료·일기 저장/수정/삭제는 원본과 챌린지 실적을 같은 DB 트랜잭션에서 반영한다. 기존 내부 실적 API는 유지한다. 탈퇴 시 원본·공개 콘텐츠·참여·실적을 함께 삭제하고 기존 탈퇴 표식으로 늦은 재전송을 막는다.
- 발도장과 코스 이용자 수는 유효한 완주 기록에서 계산한다. 반복 산책·삭제·여러 반려견으로 중복 집계하지 않는다.

## 위치 기록과 검증

좌표는 순서·시각·정확도·일시정지 구간을 가진다. 한 번에 최대 200개, 산책당 최대 10,000개와 24시간을 허용한다. 시작은 온라인에서 등록하고 단말은 전송하지 못한 배치를 보관해 같은 순서로 재전송한다. 서버는 임의로 누락 구간을 잇지 않는다.

완주 기준은 시작·도착 각 50m 이내, 진행 방향을 따른 서로 다른 코스 구간 80% 이상, 충분한 실제 유효 이동 거리다. 정확도 30m 초과, 60초 초과 공백, 일시정지 경계, 비정상적인 위치 도약은 연결 근거에서 제외한다. 코스 작성은 유효한 연속 구간만 허용한다. 이 검증은 제출 좌표의 일관성 검사이며 단말 GPS 위조를 완전히 증명하거나 방지하는 장치가 아니다. 실제 기기 화면 잠금·백그라운드·권한 철회·오프라인 품질은 Flutter 연결 단계의 검증 항목이다.

## 경계와 접근 제어

사용자 API는 Gateway와 기존 `challenge:read`/`challenge:write` scope를 사용한다. 운영 API는 `ADMIN` 역할을 추가 검사한다. Account 조회는 내부 assertion의 account audience로 최소한의 본인 프로필·반려견 정보만 요청하고 DB 트랜잭션 밖에서 수행한다. Account 장애 시 소유권을 추정하지 않는다.

모듈별 저장소 포트를 두고 공유 사용자별 트랜잭션을 통해 원본과 실적의 원자성을 유지한다. 새 SQL 마이그레이션을 추가하며 기존 참여 테이블과 API 계약은 보존한다. 사진 저장소 설정이 없으면 사진 작업은 명확한 설정 오류로 실패하고 거짓 업로드 성공을 반환하지 않는다.

## 검증과 인계

1. 정책 테스트: 연속 구간 선택, 정상·역방향·일부 반복·정지·공백·낮은 정확도·순환형 완주 판정.
2. PostgreSQL API 테스트: 소유권·공개 경계·역할, 시작/업로드/종료 재시도, 검토·중단·신고·저장, 일기 공개/비공개, 사진 확정, 자동 챌린지 반영·삭제·원본/실적 롤백·탈퇴 동시성.
3. 영향 패키지 빌드·타입·포맷·회귀 테스트와 새 마이그레이션 재실행 검증.
4. Flutter 인계 문서에 GraphQL 연산·반환 필드·위치 배치 순서·사진 전송·오류/재시도·필수 운영 설정·예시를 정리한다. 앱 화면 구현, 실제 Auth/스토리지 설정 변경, 운영 배포는 이번 작업에 포함하지 않는다.
