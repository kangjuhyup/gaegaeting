# 개개팅 산책코스 공유와 챌린지 기획안

작성일: 2026-10-05. 제품 전체 흐름에 대한 기획이며, 전체 기능의 구현 완료나 출시를 의미하지 않는다. 챌린지 백엔드는 같은 날 `packages/challenge`에 독립 구현했다. 구현 범위는 13절과 [서비스 문서](../../packages/challenge/README.md)를 참고한다. GPS 거리·완주 판정값은 시범 운영을 위한 제안값이다.

보호자가 우리 강아지의 산책코스를 소개하고, 다른 보호자가 그 코스를 따라 걸으며 발도장과 산책일기를 모은다. 코스에 함께 걷는 약속을 연결해 개개팅의 산책 매칭으로 이어지게 한다. **공유 코스는 계속 쌓이는 콘텐츠, 챌린지는 코스를 걸어볼 계기, 일기는 다시 돌아볼 개인 기록**으로 설계한다.

## 1. 목표와 이용자

- 늘 같은 길을 걷는 보호자에게 새로운 산책 장소와 구체적인 경로를 제공한다.
- 좋은 길을 알고 있는 보호자에게 코스를 소개하고 다른 강아지의 방문 후기를 받는 재미를 제공한다.
- 산책 친구를 찾는 보호자가 장소와 시간을 정한 뒤 만남을 제안할 수 있게 한다.
- 혼자 산책하는 날에도 코스 탐색·기록·챌린지를 이용할 수 있게 한다.

핵심 가설은 **다른 보호자가 직접 걸어 소개한 코스가 새로운 산책을 시작할 이유가 된다**는 것이다. 조회수보다 타인 코스의 실제 이용과 재방문으로 검증한다.

서비스 안에서는 기능 이름을 ‘산책코스’, 수집 기록을 ‘발도장’, 개인 기록 모음을 ‘산책 여권’으로 사용한다. 이름은 모두 제안이다.

## 2. 현재 서비스와 출시 범위

최초 기획 시점(챌린지 구현 전)의 작업 트리에서 확인한 사실은 다음과 같다. 배포 환경과 실제 사용자 규모는 이번 기획에서 확인하지 않았다.

### 첫 출시

1. 산책 기록으로 코스를 만들고 공개하기.
2. 주변 코스를 탐색하고 저장하기.
3. 다른 사람의 코스를 따라 걷고 완주 발도장 받기.
4. 산책일기를 남기고 원하는 기록만 코스 후기로 공개하기.
5. ‘동네 탐험대’와 ‘산책일기’ 챌린지에 참여하기.
6. 코스 상세에서 기존 산책 친구 추천 화면으로 이동하기.
7. 코스 신고·게시 중단을 처리하는 최소 운영 기능.

첫 출시의 추천 연결 버튼은 ‘산책 친구 찾기’로 표시한다. 현재 위치를 기준으로 기존 추천을 이용하며, 이 단계에서는 해당 코스나 시간대가 맞는 상대를 찾아준다고 표시하지 않는다. 코스는 로그인 후 다시 열 수 있는 링크로 저장·복사할 수 있게 한다.

### 후속 출시

실제 관심 목록·매칭·채팅 연동을 검증한 뒤 코스를 포함한 산책 제안, 시간 약속, ‘같은 시간 산책 클럽’을 추가한다. 별도 클럽 운영자나 단체 채팅 없이 1:1 약속으로 시작한다.

실시간 이용자 위치 지도, 속도·거리 경쟁 순위, 현금성 보상, AI 자동 코스 생성, 턴바이턴 길안내, 자유 댓글·팔로우는 초기 범위에서 제외한다. 네이티브 앱 전체 전환은 이 기획의 실행 범위가 아니며, 지속 기록에 필요한 클라이언트 방식은 구현 준비 단계에서 검증한다.

## 3. 핵심 이용 흐름과 화면

**코스 발견 → 상세 확인 → 혼자 또는 친구와 산책 → 완료 → 발도장·일기 → 다음 코스 발견**을 기본 흐름으로 한다. 코스 제작자는 자신의 산책 기록에서 ‘코스로 소개하기’를 선택한다.

| 화면 | 주요 내용 | 주요 행동 |
| --- | --- | --- |
| 산책 홈 | 가까운 코스 목록, 지도 전환, 진행 중 챌린지 요약 | 코스 보기, 새 산책 기록 |
| 코스 상세 | 경로, 출발·도착 장소, 거리, 소요 시간, 특징, 사진, 후기 | 산책 시작, 저장, 산책 친구 찾기 |
| 산책 중 | 코스와 현재 위치, 진행 상태, 기록 상태 | 일시정지, 재개, 종료 |
| 산책 결과 | 걸은 기록, 완주 여부, 발도장, 챌린지 진척 | 일기 작성, 내 기록 보기 |
| 코스 소개 | 공개할 구간, 코스 이름, 설명, 사진, 특징 | 공개 미리보기, 게시 신청 |
| 산책 여권 | 내 산책일기, 수집한 발도장, 작성·저장한 코스 | 기록 보기, 코스 다시 걷기 |
| 챌린지 상세 | 조건, 기간, 내 진행 상황, 보상 | 참여, 대상 코스 찾기 |

기존 하단 메뉴에 ‘산책’을 추가한다. 산책 화면 안에서 코스와 챌린지를 탐색하고, 개인 산책 여권은 산책 홈과 내 정보에서 접근한다. 가입·보호자·반려견 등록 흐름은 기존 앱과 연결한다.

코스 카드 예시:

> **두부의 저녁 단골 산책길**
>
> 1.2km · 작성자 기준 휴식 포함 약 30분 · 순환형
>
> 흙길 있음 · 계단 없음 · 그늘 많음
>
> “중간 잔디 구간에서 냄새 맡으며 쉬기 좋아요.”
>
> 산책 시작 / 저장 / 산책 친구 찾기

이 문서의 거리·시간·코스 이름은 예시다. 실제 카드에는 저장된 코스 데이터만 표시한다.

## 4. 코스 만들기와 탐색 정책

### 코스 만들기

- 로그인하고 반려견을 등록한 이용자가 자신의 산책 기록에서 코스를 만든다. 한 산책에 반려견 여러 마리를 선택할 수 있지만, 산책 횟수는 한 번으로 센다.
- 실제로 기록된 연속 구간에서 출발·도착 위치를 선택한다. 지도에 임의의 선을 그어 완성 코스로 게시하는 기능은 첫 출시에서 제공하지 않는다.
- 집에서 공원까지의 이동 구간처럼 공개하고 싶지 않은 시작·끝부분을 잘라낼 수 있다. 제외한 좌표와 원본 촬영 위치는 공개 응답에 포함하지 않는다.
- 이름, 한 줄 소개, 출발·도착 장소 이름, 반려견, 실제 경로를 필수로 한다. 사진은 선택이며, 사진이 없으면 경로 지도를 대표 이미지로 쓴다.
- 거리와 순환형 여부는 공개할 경로로 산출한다. 소요 시간은 선택 구간의 휴식 포함 기록을 참고값으로 표시한다. 모든 강아지에게 동일한 소요 시간을 보장하지 않는다.
- 노면, 계단 유무, 그늘, 횡단보도, 쉴 곳을 선택형 정보로 받는다. 미입력은 ‘정보 없음’으로 표시하고 ‘없음’으로 추정하지 않는다.
- 편도형과 순환형을 지원한다. 첫 출시의 따라 걷기는 작성자가 기록한 방향을 기준으로 한다.
- 위치 기록이 끊긴 구간은 직선으로 이어 붙이지 않는다. 연속으로 확인된 구간만 선택해 게시할 수 있다.

### 공개와 수정

코스는 ‘초안 → 검토 중 → 공개’ 순서로 진행한다. 첫 시범 지역에서는 운영자가 보행 가능한 공개 장소인지, 반려견 출입 제한 안내가 있는지, 게시 정보가 적절한지 확인한다. 검토는 현장의 모든 조건을 보증하는 인증으로 표시하지 않는다.

반려한 코스는 사유를 보여주고 초안으로 되돌린다. 작성자는 공개를 중단할 수 있고, 운영자는 신고를 확인해 게시를 중단하거나 수정 요청할 수 있다. 중단된 코스는 검색·신규 시작 대상에서 제외한다.

공개 경로는 덮어쓰지 않는다. 경로를 바꾸려면 기존 코스를 중단하고 새 코스로 게시한다. 이름·소개·사진·특징 수정은 재검토 후 반영한다. 기존 완주 기록과 발도장은 당시의 코스 이름·식별자를 유지하며, 현재 공개 중인 것처럼 다시 노출하지 않는다.

### 탐색

- 현재 위치 또는 사용자가 고른 동네를 기준으로 코스를 탐색한다. 위치 권한 없이도 동네 선택과 코스 열람을 허용한다.
- 기본 정렬은 출발점까지의 가까운 순서다. 검색 범위를 벗어나는 코스로 자동 확대하지 않고 이용자가 지역을 바꾸게 한다.
- 거리·순환형 여부·노면·계단 유무를 필터로 제공한다. 지도와 동등한 내용의 목록을 함께 제공한다.
- 코스 상세에는 작성자와 반려견, 특징의 작성 주체, 최근 후기 날짜, 현재 게시 상태를 표시한다.
- 코스가 없는 동네에는 빈 상태와 ‘다른 동네 보기’, ‘내 산책 기록하기’를 제공한다. 샘플 코스를 실제 이용자 콘텐츠처럼 표시하지 않는다.

## 5. 따라 걷기와 완주 인정

코스 선택 후 위치를 확인하고, 출발 지점에 도착하면 산책을 시작한다. 코스 없는 일반 산책도 기록할 수 있으며, 해당 기록에서 새 코스를 만들 수 있다. 동시에 진행할 수 있는 산책 기록은 계정당 하나다.

산책 상태는 ‘진행 중 ↔ 일시정지 → 종료’로 관리한다. 코스를 따라 걷는 산책은 종료 후 ‘기록 확인 중 → 완주 인정’ 또는 ‘일부 구간 산책’으로 결과를 표시한다. 코스 없는 일반 산책은 완주 판정 없이 개인 기록으로 저장한다. 네트워크가 끊기면 서버 확인 전에는 보상을 확정하지 않는다.

첫 출시에서는 온라인 상태에서 산책 시작과 챌린지 참여를 서버에 등록한다. 시작 후 통신이 끊기면 단말에 기록하고 재연결 시 전송한다. 시작 등록에 실패하면 시작된 것처럼 표시하지 않고 재시도를 제공한다.

**완주 제안 기준:** 출발·도착 지점 각각 50m 이내에서 위치가 확인되고, 원래 경로 길이의 80% 이상을 진행 방향에 따라 걸은 기록이 있어야 한다. 구체적인 계산과 보정은 구현 시 실제 산책 데이터로 검증한다.

- 진행률은 코스의 서로 다른 구간을 통과한 비율이다. 같은 구간 왕복이나 출발점 주변 체류만으로 채우지 못한다.
- 기록 순서와 실제 이동을 함께 확인한다. 순환형 코스의 출발·도착 지점에 가만히 머물러도 완주되지 않아야 한다.
- 초기 판정에서는 위치 정확도 오차가 30m를 넘는 점과 60초를 넘는 기록 공백을 진행률 연결 근거로 사용하지 않는다. 값은 시범 측정 후 조정하며 적용 정책을 기록에 남긴다.
- 잠깐 다른 길로 가거나 쉬어도 실패 처리하지 않는다. 돌아온 뒤 이미 걸은 진행률에서 이어간다. 쉬는 시간과 완주 속도에 제한을 두지 않는다.
- 종료 시 조건이 부족하면 ‘일부 구간 산책’으로 저장한다. 사진·일기를 남길 수 있지만 완주 발도장과 탐험 챌린지 실적은 지급하지 않는다.
- GPS 이상이나 권한 철회 시 기록이 원활하지 않음을 알리고, 확보한 구간을 보존한다. 위치를 다시 확보해 재개할 수 있다.
- 업로드 재시도·종료 버튼 재클릭·앱 재접속으로 같은 산책이 중복 완료되거나 보상이 중복 지급되지 않는다.
- 다른 사람의 실시간 위치나 현재 이 코스를 걷는 사람 목록은 제공하지 않는다.

화면을 잠그거나 잠깐 다른 앱을 사용해도 기록이 유지되고 복구 가능한 경험을 정식 공개의 품질 조건으로 둔다. 현재 웹 UI에서 충족한다고 가정하지 않는다. Chrome은 페이지가 중단·폐기될 수 있음을 명시하므로, 브라우저 위치 기능만으로 지속 기록을 보장할 수 있다고 보지 않는 것이 이 기획의 판단이다. [Chrome Page Lifecycle 문서](https://developer.chrome.com/docs/web-platform/page-lifecycle-api)

구현 준비 단계에서 실제 지원 기기의 화면 잠금·앱 전환·통신 단절을 검증하고, 결과에 맞는 기록 방식을 선택한다. 미충족 상태는 화면을 켜둔 제한적 사용성 실험에만 사용하며, 일상 산책용 정식 기능의 완료로 간주하지 않는다.

## 6. 산책일기와 발도장

- 산책을 종료하면 이동 거리·총 소요 시간·참여 반려견·코스가 개인 기록으로 남는다. GPS 누락 구간을 추정 거리로 채우지 않는다.
- 일기는 기분 선택과 사진 한 장으로 작성할 수 있다. 글은 선택이다. 일반 기록은 사진 없이도 저장할 수 있다.
- 일기 공개 기본값은 ‘나만 보기’다. 사용자가 ‘코스 후기로도 공개’를 선택하면 사진·글·기분만 코스에 노출한다. 실제 이동 궤적과 정확한 출발 시각은 공개하지 않는다.
- 공개 후기는 완주 인정된 산책에만 연결한다. 계정당 코스 후기 한 개를 유지하고 이후 산책에서 수정할 수 있다. 최신 방문 날짜를 표시한다.
- 후기 공개를 해제하면 코스에서 제거하지만 개인 일기는 남긴다. 일기 자체를 삭제하면 해당 공개 후기도 제거한다.
- 코스 첫 완주 시 해당 코스의 발도장 한 개를 받는다. 반복 완주는 개인 횟수로 쌓고, 같은 발도장을 여러 개 지급하지 않는다.
- 코스 상세의 ‘걸어본 보호자 수’는 서로 다른 완주자 수이며 작성자를 제외한다. 동일 이용자의 반복 산책이나 반려견 수로 부풀리지 않는다.
- 작성자도 자기 코스를 걸어 개인 기록을 쌓을 수 있지만, 타인 코스 탐험 실적으로 인정하지 않는다.
- 계정 탈퇴 또는 산책 기록 삭제 시 개인정보와 연결된 기록을 삭제한다. 삭제한 산책의 공개 후기·공개 이용자 집계와 진행 중 챌린지 실적을 제거한다. 획득한 보상도 근거가 사라졌을 때 재계산한다.

## 7. 챌린지 구성

이용자가 ‘참여하기’를 누르면 시작한다. 과거 기록은 소급하지 않는다. 시간대는 한국 시간으로 표시하고, 기간은 참여 시점부터 시작해 참여 날짜를 1일째로 계산한 마지막 날 23:59:59까지로 한다. 한 번의 산책이 조건을 충족하는 여러 챌린지에 동시에 반영될 수 있다.

| 챌린지 | 조건 제안 | 인정 단위와 보상 | 출시 |
| --- | --- | --- | --- |
| 우리 동네 탐험대 | 참여 후 14일 동안 다른 보호자가 소개한 서로 다른 코스 3개 완주 | 서로 다른 코스 1개당 1칸. 완성 시 탐험대 뱃지 | 첫 출시 |
| 우리 강아지 산책일기 | 참여 후 7일 동안 서로 다른 3일에 산책일기 작성 | 당일 산책의 사진 1장+기분 선택. 1일 1칸. 완성 시 기록 카드 | 첫 출시 |
| 같은 시간 산책 클럽 | 참여 후 14일 동안 선택한 시간대에 같은 코스로 친구와 3일 산책 | 양측이 확인한 공동 산책 1일 1칸. 완성 시 시간대 뱃지 | 후속 출시 |

공통 정책:

- 계정별 실적이다. 반려견별로 중복 지급하지 않는다. 챌린지 한 종류에 진행 중 참여는 하나만 허용한다.
- 종료 시각과 달성 조건을 참여 전에 보여준다. 참여 후에는 기간·횟수·대상 조건을 바꾸지 않는다.
- 탐험대 실적은 산책 종료 시점, 일기 실적은 산책 종료일과 일기 저장 시점을 기준으로 한다. 일기는 해당 산책을 종료한 한국 날짜 안에 저장해야 하며, 기록된 이동이 있는 산책이어야 한다. 수동으로 과거 날짜를 입력해 실적을 만들 수 없다.
- 비공개 일기도 인정한다. 일기 챌린지는 일반 산책과 일부 구간 산책도 인정하지만, 이동 없이 시작·종료한 기록은 제외한다.
- 기한 내 종료한 오프라인 산책은 종료 후 24시간 안에 동기화한 경우 반영하는 것을 제안한다. 서버는 시작된 세션과 기록 시각을 검증한다. 기한 지난 뒤 새로 만든 세션은 인정하지 않는다.
- 동기화 유예를 지난 기록도 개인 기록으로 저장할 수 있지만, 종료된 챌린지 실적으로 소급하지 않는다.
- 오프라인 일기는 기한 내 같은 날 저장한 로컬 기록을 동일한 24시간 유예 안에 검증한 경우에만 반영한다. 기한 후 새로 작성한 일기를 소급하지 않는다.
- 최종일 이후에는 최대 24시간 ‘기록 확인 중’ 상태를 거쳐 종료한다. 기간 내 동기화가 끝난 달성은 바로 확정할 수 있다.
- 삭제 또는 부정 기록 무효화로 근거 실적이 사라지면 진행률·보상을 재계산한다. 단순 코스 게시 중단만으로 과거의 정상 산책 실적은 취소하지 않는다.
- 미달성은 기록을 보존한 채 종료한다. 연속 일수 초기화나 벌점을 두지 않는다. 다음 참여는 새 기간으로 시작한다.
- 보상은 발도장·뱃지·산책 기록 카드로 한정한다. 첫 출시의 기록 카드는 앱 안에서 조회하며 별도 자동 앨범 영상 제작은 포함하지 않는다.

## 8. 코스를 통한 매칭과 시간대 챌린지

후속 단계에서는 코스 상세의 ‘이 코스 같이 걷기’에서 날짜·시간을 고르고, 기존 매칭 관계에 있는 상대에게 코스가 담긴 약속을 제안한다. 새로운 상대는 기존 추천·관심·상호 수락 과정을 먼저 거친다. 코스 작성자에게 자동으로 메시지나 약속을 보내지 않는다.

약속은 ‘제안 → 수락 → 예정 → 완료 확인 대기 → 함께 산책 완료’로 진행한다. 거절·취소·시간 변경을 지원하고, 시간 변경은 상대방의 재수락을 받는다. 수락되지 않은 약속은 참여로 집계하지 않는다.

- 시간대 챌린지 참여 시 코스 하나와 시간대를 선택한다. 초기 시간대 제안은 아침 06:00~10:00, 저녁 18:00~22:00이며 시작 시각을 기준으로 한다. 끝 시각 경계는 포함하지 않는다.
- 양측이 수락한 동일 약속에 자신의 산책 기록을 연결한다. 두 기록 모두 같은 코스에서 완주되고, 서로의 산책 시간이 겹치며, 선택 시간대에 시작해야 한다.
- 약속 시간 전후 30분 안에 양측이 시작한 기록을 대상으로 하고, 마지막 종료 후 24시간 안에 양측이 함께 걸었음을 확인해야 공동 실적이 된다. 챌린지 기간 안에 종료한 산책만 대상이다.
- 위치가 가깝다는 이유만으로 함께 걸었다고 판정하지 않는다. 한쪽만 완료 확인하면 개인 완주만 인정한다.
- 한 약속에는 두 계정만 참여하며 각 계정에는 자기 실적만 반영한다. 같은 날 여러 약속을 완료해도 시간대 챌린지에는 한 번만 인정한다.
- 친구는 회차마다 달라도 된다. 같은 상대 반복 만남을 필수 조건으로 두지 않는다.
- 참여 중 코스·시간대를 변경하려면 기존 참여를 종료하고 새로 참여한다. 중단된 코스는 새 약속을 만들 수 없고, 진행 중 챌린지는 기록을 보존한 채 종료·재참여를 선택하게 한다.

## 9. 공개 정보와 운영

| 정보 | 기본 접근 범위 |
| --- | --- |
| 공개 승인된 코스·소개·공개 후기 | 로그인한 서비스 이용자 |
| 작성자의 원본 산책 궤적, 타인의 실제 산책 경로 | 해당 기록의 소유자 |
| 개인 일기·사진·정확한 산책 시각 | 작성자. 별도로 선택한 후기 항목만 공개 |
| 동행 약속과 시간 | 수락 과정의 두 당사자 |
| 운영 검토 자료 | 업무에 필요한 운영 권한으로 제한 |

공유 링크도 로그인 이후에 같은 공개 범위를 적용한다. 공개 사진에는 위치 메타데이터가 남지 않게 한다. 원본 산책과 공개 코스는 별도 데이터로 취급하고, 공개를 중단하거나 후기를 비공개로 전환하면 기존 이미지 URL 접근도 함께 제한한다.

코스 신고 항목은 통행 불가, 반려견 출입 제한, 잘못된 경로, 개인정보 노출, 부적절한 내용으로 시작한다. 신고 횟수만으로 자동 삭제하지 않고 운영자가 확인한다. 보행 불가 등으로 게시를 중단하면 신규 시작을 막고 진행 중 이용자에게 코스 상태 변경을 알린다. 진행 중 기록은 개인 기록으로 종료할 수 있다.

게시 중단 전에 시작한 산책은 원래 코스 기준으로 완주 여부를 판정할 수 있지만, 계속 걸으라고 유도하지 않는다. 삭제된 코스의 경로는 공개 링크로 다시 열리지 않게 하고, 개인의 정상 완주 요약은 남길 수 있다.

원본 좌표는 산책 기록 유지에 필요한 동안만 보관하고, 삭제 요청 시 서비스의 원본·공개 파생물·단말 임시 기록에서 제거한다. 코스의 원본 산책을 삭제할 때는 해당 공개 코스도 함께 제거된다는 결과를 먼저 안내한다. 다른 이용자가 직접 기록한 산책과 정상 완주 요약은 유지하되, 삭제된 작성자의 경로·사진·신원은 다시 제공하지 않는다. 백업과 로그의 보존 기간은 서비스 공통 정책에 맞춰 구현 설계에서 문서화한다. 분석 이벤트에는 원본 좌표·사진·일기 내용을 넣지 않는다.

## 10. 시범 운영과 성공 판단

한 동네에 운영자가 직접 확인한 코스 5~10개를 먼저 등록하고 소수 이용자로 시작하는 것을 제안한다. 짧은 순환형, 흙길이 있는 코스, 계단 없는 코스처럼 선택 이유가 다른 코스를 준비한다. 운영자 코스임을 명시하고, 일반 보호자의 코스와 동일한 이용 흐름을 제공한다.

첫 검증 질문은 ‘코스를 본 사람이 실제로 그 길을 걸었는가’, ‘걸어본 뒤 다른 날에도 다시 사용했는가’, ‘어떤 정보가 코스 선택에 도움이 됐는가’다. 기록 누락과 콘텐츠 매력 부족을 구분해 살핀다.

| 지표 | 정의 |
| --- | --- |
| 핵심 이용 지표 | 주간에 타인이 작성한 코스를 한 번 이상 완주한 고유 이용자 수 |
| 코스 시작률 | 코스 상세 조회 후 24시간 내 동일 코스를 시작한 이용자-코스 쌍 / 상세를 본 이용자-코스 쌍 |
| 완주율 | 완주 인정된 코스 산책 수 / 시작한 코스 산책 수. 기록 오류·중도 종료 사유를 따로 집계 |
| 7일 재이용률 | 첫 타인 코스 완주 다음 날부터 7일 안에 코스 산책을 다시 시작한 이용자 / 7일 관찰이 끝난 첫 완주자 |
| 콘텐츠 활용률 | 공개 후 14일 이내 작성자 외 이용자가 완주한 코스 / 14일 관찰이 끝난 공개 코스 |
| 추천 연결률 | 코스 상세에서 산책 친구 찾기를 선택한 이용자 / 코스 상세를 본 이용자 |
| 후속 매칭 성과 | 코스에서 시작한 제안 중 상호 수락된 약속과 공동 산책 완료 수. 첫 출시의 버튼 클릭과 구분 |

절대 전환율 목표를 현재 실적처럼 만들지 않는다. 시범 운영에서 기준선을 얻고 기록 성공률·코스 부족·선택 이유를 확인한 뒤 지역 확대 여부를 결정한다.

아래는 제품 전체 구현 순서다. 챌린지와 코스·산책·일기 백엔드는 구현했으며, 화면 연결은 Flutter 앱 에이전트가 이어서 수행한다. 상세 구현 계약은 [백엔드 구현 계획](2026-10-05-walking-backend-implementation.md)을 따른다.

| 1 | 실제 기기에서 지속 위치 기록·중단 복구·완주 판정 검증. 지도 공급사와 기록 방식을 선정하고 지원 범위를 명시 | frontend, backend, qa |
| 2 | 코스·산책 기록·공개 범위·완주 정책·삭제 계약 설계. 1의 결과 반영 | backend, document |
| 3 | 코스 등록·검토·탐색·저장·따라 걷기의 처음부터 끝까지 동작하는 흐름 | backend, frontend, qa |
| 4 | 일기·후기·발도장·탐험대와 일기 챌린지. 산책 완료·수정·삭제에 따른 집계 연결 | backend, frontend, qa |
| 5 | 추천 연결, 신고 처리, 분석 이벤트, 시범 지역의 콘텐츠 준비와 사용성 검증 | frontend, backend, qa, document |
| 6 | 실제 관심·매칭·채팅 연동 이후 코스 약속·공동 완료 확인·시간대 챌린지 | backend, frontend, qa |

사용자가 결정한 챌린지 분리와 원본 기능 추가를 반영한 경계는 다음과 같다.

- 사용자 화면과 이동은 `packages/integration-ui`, 공통 UI는 `packages/ui-common`에서 다룬다. 새로운 화면의 직접 접근·새로고침 경로도 함께 반영한다.
- 챌린지는 **`packages/challenge` 독립 서비스**로 두고 참여·실적·보상 규칙과 전용 DB를 소유한다. Match를 의존하지 않으며 Gateway에서 선택적으로 연결한다.
- `packages/challenge` 안의 Route·Walk·Diary 모듈이 공개 경로·본인 GPS·일기 본문·사진 메타데이터를 별도 원본 테이블에 저장한다. 사진 바이트는 비공개 스토리지에 저장한다. 검증한 결과만 Activity에 같은 DB 트랜잭션으로 반영하며 실적 테이블에는 GPS·본문을 중복 저장하지 않는다. Match의 현재 위치 갱신과는 별도 기록이다.
- Account의 사용자·반려견 식별자를 참조하고 프로필의 원본 소유권은 Account에 둔다. 소유자·공개 상태 검증은 클라이언트 요청 값에만 의존하지 않는다.
- Gateway는 공개·비공개 응답 경계를 지키고, 이미지 저장은 기존 저장소 기능의 접근 제어·공개 전환·삭제 요건을 확인한 뒤 연동한다.
- 운영 화면은 `packages/admin-ui`에 코스 검토·신고 처리를 추가하는 방향으로 잡는다. 운영 권한 검증도 서버에서 수행한다.
- 후속 약속은 매칭 관계, 코스, 예정 시각을 연결한다. 메시지 원문 파싱으로 약속이나 공동 완료를 추정하지 않는다.

핵심 데이터는 코스, 개인 산책 기록, 일기, 공개 후기, 발도장, 챌린지 참여·실적이다. 후속 단계에서 약속을 추가한다. 코스 이용 시작 시 기준 경로를 고정하고, 완료 확인 결과 하나로 발도장과 챌린지를 갱신한다. 서버 재시도에도 결과가 같아야 하며, 삭제·무효화 시 관련 집계를 함께 재계산한다.

## 12. 수용 기준

| 시나리오 | 확인할 결과 |
| --- | --- |
| 코스 제작자가 원본의 집 근처 구간을 제외하고 게시 | 다른 계정의 API 응답·지도·사진 메타데이터에 제외한 위치가 나타나지 않음 |
| 검토 중·반려·중단된 코스 | 일반 검색 및 신규 산책 시작 불가. 작성자에게 상태·사유 표시 |
| 위치 권한 거절 | 동네 선택·탐색·저장 가능. 산책 기록 시작 시 필요한 권한을 안내 |

| 정상 편도·순환형 산책, 잠깐 경로 이탈·휴식 | 유효 구간을 유지하고 완주 조건을 충족하면 인정 |
| 출발점 정지, 일부 구간 왕복, 시작·끝만 방문 | 경로 진행률이 부풀려지지 않고 완주되지 않음 |
| 화면 잠금·앱 전환·GPS 누락·네트워크 단절 | 지원 기기에서 기록 보존·복구 검증. 누락 구간을 임의 완주 처리하지 않음 |
| 같은 종료·업로드 요청 재전송 | 산책·발도장·챌린지 실적이 각각 한 번만 반영 |
| 사진 없는 기록, 비공개 일기, 공개 후기 전환·해제 | 개인 기록은 저장 가능. 챌린지별 사진 조건 준수. 공개 선택 항목만 노출·회수 |
| 동일 코스 반복, 자기 코스, 여러 반려견 | 개인 기록과 보상 인정 단위가 6·7절 정책대로 구분됨 |
| 참여 전 기록, 마지막 날 경계, 오프라인 동기화 | 기간·인정 날짜·24시간 유예 정책대로 포함·제외되고 사유를 확인 가능 |
| 산책·일기 삭제 또는 계정 탈퇴 | 공개 데이터 접근 제거, 관련 실적·집계·보상 재계산 |
| 모바일 목록·지도·기록 조작 | 지도 없이도 코스 정보 접근. 320px 화면에서 핵심 동작 가능. 버튼 명칭·상태를 보조기기로 구분 |
| 새 화면 직접 열기·새로고침 | 로그인 후 의도한 코스로 복귀하고 앱 화면이 정상 표시 |
| 후속 단계의 약속 미수락·한쪽만 확인·취소 | 공동 실적 미지급. 정상 개인 산책 기록은 보존 |
| 후속 단계의 같은 코스·시간대·상호 완료 | 정책에 맞는 공동 산책만 해당 날짜에 한 번 반영 |

구현 시에는 저장소의 고정 런타임을 활성화하고 영향 범위의 테스트를 수행한다. UI는 기존 `pnpm test:ui`와 해당 패키지 typecheck·build, Challenge는 정책·저장·권한·실적 전달 테스트를 기준으로 확장한다. 화면 잠금과 위치 기록 품질은 단위 테스트만으로 통과 처리하지 않고 실제 산책으로 검증한다.

## 13. 백엔드 구현 현황

2026-10-05 기준 `packages/challenge`에 탐험대·산책일기 챌린지와 코스 작성/검토/탐색/저장/신고, 산책 시작/GPS/정지/재개/종료/완주/여권, 일기 본문/기분/사진/공개 후기를 구현했다. 내부 기능은 Catalog·Participation·Activity·Route·Walk·Diary로 나눈다.

원본과 실적은 같은 사용자별 트랜잭션에서 갱신한다. 원본 GPS·일기 본문은 보관하되 본인 조회와 공개 조회의 반환 범위를 나누며, 공개 코스에는 선택한 구간만 포함한다. 사진은 실제 PNG를 검증하고 메타데이터를 제거해 별도 객체로 확정한다. 삭제/탈퇴는 원본·실적을 제거하고 파일 삭제 작업을 예약한다.

독립 DB 마이그레이션, Gateway subgraph·scope, 로컬 실행·이미지 빌드 대상과 PostgreSQL API 검증도 포함한다. 최신 API·정책·실행 방법은 [Challenge README](../../packages/challenge/README.md), 앱 연동 순서는 [Flutter 인계 문서](../../packages/challenge/docs/flutter-integration.md), 수행한 검증은 [검증 기록](../../packages/challenge/docs/verification.md)을 기준으로 한다.

이번 범위는 백엔드다. Flutter 화면·실기기 위치 수집 검증, 실제 Account 탈퇴 이벤트 전달 연결, 운영 스토리지/인증 설정과 배포, 보상 이미지 생성은 별도 단계다. 같은 시간 산책 클럽도 후속 출시 범위를 유지한다. 따라서 12절의 앱/운영 수용 기준을 모두 충족했다는 의미는 아니다.
